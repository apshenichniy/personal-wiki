# Provider accounting authority (P6 in progress)

`ProviderLedger` is a service-owned Effect SQL module over a private SQLite accounting file. Staging and production must share this file on the single CX33. Library snapshots, namespace resets, or a Runner restart must not create a new campaign/month allowance. The module is not wired into HTTP or the live Runner yet; this is an implementation checkpoint, not a completed acquisition feature.

Every acquisition operation keeps immutable job/window/namespace, input, plan identity, provider/platform/retrieval reserves, start intent, exact run/storage/build identities, raw-page checkpoints, and observed costs. A start permit is issued once. Its lost response leaves an unresolved liability; only exact response evidence or a trusted operator reconciliation can identify or dismiss an ambiguous start. Unknown/running work blocks another provider dispatch across namespaces.

Budgets use integer nanodollars and upward rounding of reported USD. The job limit is USD 0.25, the UTC start-month limit USD 5, and the acceptance campaign USD 2. Prior known usage is imported idempotently with an evidence digest. The Actor event ceiling is distinct from its bounded platform-usage reserve. Stable reported run usage replaces those reserves only after terminal evidence, two matching cost samples separated by at least ten seconds, and archive completion. The retrieval allowance remains conservatively booked; it is not represented as a measured provider charge. Late increased costs remain visible, and an overcharge quarantines new spending.

No configuration means no paid permission. Provisioning and absent-run reconciliation are trusted Service/operator methods, not Runner-facing APIs. Hashes are references to evidence, not independent proof that privacy, pricing or ownership was established. Live enablement must verify that evidence and bind the job-authorized API to this module. Runner now has a [bounded transport and local dispatch journal](../../../runner/src/apify/README.md), verified independently. Shared physical pipeline admission, job cancellation/fencing, transport composition, exact-Actor normalization, R2 upload/readback and live privacy/accounting checks remain to be integrated before P6 closes.

Checks: `mise exec -- bun test tests/provider-ledger.test.ts`. Synthetic coverage includes actual concurrent OS processes against one accounting database, SIGKILL after a persisted dispatch intent, namespace-shared quotas, UTC rollover, repeated/late status and cost updates, cancellation, immutable bounded page registration and fresh-connection recovery. Ordinary checks make no provider calls.
