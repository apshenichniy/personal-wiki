# Source processing

`prepareX(input, acquire)` turns a submitted X URL and archived provider observations into a versioned `PreparedSource`. It is a sequential Effect program with one narrow acquisition boundary. It does not call Apify, access Git/SQLite/R2, choose an agent or publish notes.

The acquisition adapter receives a deterministic key, mode, total unique-result allowance and explicit per-target allocations. It must persist the effective policy and request options, enforce service-owned deadlines/budgets, perform at most one authorized external dispatch, archive raw pages, and return verified asset IDs/checksums. On recovery it replays retained results for the same key/options before considering another dispatch. P6 implements that boundary. This module never treats repeating a plan as permission to repeat a paid request.

The v1 X adapter input preserves decimal IDs, original/long text, author/parent/conversation/quote/Article relationships and references. `parentStatus` distinguishes a known root, a known reply and unavailable relationship metadata. Missing metadata must stay unknown. Article `bodyStatus` cannot upgrade a preview into an acquired body. Acquired-page row order must preserve raw-row locators; raw content and diagnostics remain retained even when a row is malformed, unrelated or outside the admitted bound.

The processor resolves an author chain only through compatible authorship and parent edges. A selected participant reply is independent, even when its conversation root is available. Uncertain resolution does not create aliases. Supplied known sources are authoritative published identities; two identities intersecting one resolved material produce a conflict instead of a merge.

Acquisition prioritizes anchor/context, author material and first-level quote/Article before direct and Latest discussion. The shared parent/quote allowance is 30 by default. Discussion has a shared 200-post ceiling: initial allocations are 100 direct, 75 Latest and a 25-post nested reserve. Unused slots can move to nested acquisition, distributed across branches with explicit per-target ceilings. New author material discovered during discussion is reclassified before the next optional request; its quote and still-unused Article allowance take priority. An Article already dispatched consumes the single slot; a later higher-priority discovery is reported explicitly without starting a second Article. Known author-chain overflow cannot borrow discussion/context capacity, and repaired parents of unrelated candidates stay in raw evidence rather than becoming prepared context. Provider over-return, duplicates, missing ancestry and stop reasons remain visible. Empty results and provider success never establish exhaustive coverage.

The output keeps original-language text, per-observation acquisition provenance, text-variant digests, distinct article material, unprocessed references and separate raw/admitted/presented counts. Long-post text takes precedence over a legacy excerpt. No LLM-based filtering or popularity ranking happens here: substantive corrections and disagreements remain available to P8's curator. Source instructions remain data.

The prepared-text limit is a UTF-8 byte admission check. Required acquired text is never silently truncated to fit. Capacity/unavailable/conflict outcomes retain the acquisition manifest and expose no publishable materials. The service assigns canonical IDs and binds this result to retained captures; model token admission and quality validation remain separate gates. Current first-slice application schemas permit at most 50 main aliases and 300 observations per capture; increasing capture policy limits beyond those representation bounds requires coordinated schema/version work.

Verify with `mise exec -- bun test tests/source-processing.test.ts`. Run `mise exec -- bun run tools/processing-demo.ts` for a complete synthetic middle-of-thread example, including original text, requests, provenance and coverage. The command validates a JSON schema round trip before printing. No private captures or provider credentials are used.
