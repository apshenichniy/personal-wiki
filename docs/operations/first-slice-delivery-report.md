# First X-to-wiki slice: delivery evidence

**2026-10-19 — G1–G5 passed; ready for owner acceptance.** This report concerns the approved first slice, not the entire product roadmap. G6 is reserved for the owner; the [delivery epic](https://github.com/apshenichniy/personal-wiki/issues/23) stays open for that observation.

## Delivered boundary

The private web application accepts an X post/thread URL, retains bounded Apify evidence in private R2, runs subscription Codex in the single server-wide agent slot, and publishes detailed Russian notes with inline post citations. The reader offers lexical search across notes and retained source text, source switching, original downloads, related notes and job status/actions. The VPS owns execution, Git knowledge history, SQLite state and publication; the owner's Mac is not a runtime dependency.

Native apps, offline clients, native sharing, Clipper, Telegram ingestion, the knowledge MCP facade, Claude execution, PDF/YouTube/transcription and semantic search remain subsequent slices. The existing Telegram MCP is preserved; its presence does not mean the knowledge-ingestion bot has been implemented. The [Native Inbox + Share plan](../plans/native-inbox-share.md) is the next product direction, subject to its own specification.

## Live quality and costs

The staging corpus contains five real notes from four submitted source cases and one clearly synthetic deployment fixture. The accepted examples cover a detailed coding-practice post with attribution corrections; a post with a separately retained X Article; a substantive discussion; and a root/author-continuation chain submitted from its middle. Original language is retained. Russian notes distinguish main content, discussion, source claims and capture limitations, with inline links to exact X posts.

Earlier live attempts exposed three integration defects: nested systemd/sandbox policy, raw-asset grants on retained retry, and incomplete per-material citation repair feedback. PRs [#55](https://github.com/apshenichniy/personal-wiki/pull/55), [#56](https://github.com/apshenichniy/personal-wiki/pull/56) and [#57](https://github.com/apshenichniy/personal-wiki/pull/57) resolved them with regressions. The citation validator remained strict. Final retained retries succeeded with one Codex launch each and zero new Apify operations; the author-chain case used one initial launch plus one bounded repair. Structural validity and semantic review are recorded separately.

Before the final production case, new staging provider usage reported **$0.069282701**. Conservative new liability including reserved retrieval overhead was **$0.569282701**. Imported prior usage was **$0.124365903**, including **$0.102731147** from this acceptance campaign and **$0.021634756** from the earlier pilot. Thus the staging checkpoint held **$0.672013848** against the $2 campaign ceiling and **$0.693648604** against the $5 monthly ceiling. These are conservative accounting figures, not an invoice or a claim that delayed charges are zero. After the production case, 31 operations reported **$0.077944940** of new provider usage. With conservative reserves (one terminal operation still had an unsettled cost sample), the campaign held **$0.877347408** and the month **$0.898982164**. The largest job liability was **$0.205333560**, below $0.25. All original bytes were archived. Unsettled charges keep their reservation; they are not treated as zero or erased on completion. The private `production-final-metrics.json` records this checkpoint.

Production was exercised through the actual owner browser: Pocket ID login, an `fxtwitter.com` submission, durable job status and reading the published note. The first model launch returned an explicit model-capacity refusal and failed safely with retained capture. The UI action to retry the retained source then succeeded with one Codex launch, without any additional Apify operations or a model/account switch. The production library contains that real note; the separate staging corpus was not copied into it.

## Operating and reviewing the result

- [Release and rollback runbook](releases.md): verified archive selection, controller ownership, private dispatch settings and same-byte promotion.
- [Recovery runbook](recovery.md): backup status, encrypted restore, session revocation, external-cost reconciliation and controlled authority transfer.
- [CI access boundary](ci-access.md): ephemeral Tailscale workload identity and restricted deployment user.
- Private evidence: the owner's `~/.config/personal-wiki/evidence/p11/`, `p12/`, `p13/` directories and root-only VPS acceptance/backup inventories. These contain captured material, run identities and exact observations; they are deliberately excluded from public Git and CI.

Only production dispatch is enabled after promotion; staging remains a separate private acceptance library. The application stores sources and knowledge on the VPS/R2, with encrypted independent backup. Public URL access does not grant access to notes or originals. Cloudflare may reject generic automated HTTP clients before the origin; ordinary browser access and direct application denials were checked independently.

G6 checklist for the owner:

1. Switch the Mac off and open the private production wiki on the actual iPhone; sign in with the existing passkey.
2. Submit an X link, leave/reopen the page, and confirm that the server completes the job and shows its note.
3. Read the Russian detail, follow several inline post citations, switch to the retained original and open/download it.
4. Search for a topic and an original-language term; assess whether main arguments, examples and qualifications are preserved and the discussion is useful.
5. Record defects or acceptance in the delivery epic. Physical-device success and semantic approval belong to this owner observation.

Known first-slice limits: bounded X snapshots do not guarantee complete threads; supported linked X Articles are distinct from arbitrary external pages; video/media processing is deferred. Search is lexical without Russian stemming: inflected word forms may require a different exact term. The web reader does not yet provide offline replication. Provider/subscription authentication or unresolved paid-run identity can require explicit operator recovery. An unclassified model-capacity refusal currently terminates with retained evidence; the owner can retry the saved capture when capacity returns. The UI still exposes some technical status terms, and one generated staging note repeats a summary heading; presentation and curation refinements remain possible after owner review. The source archive is encrypted in backup but a root compromise with backup credentials can delete backups; immutable offsite retention is not implemented. The existing shared VPS and its finite storage remain operational constraints.
